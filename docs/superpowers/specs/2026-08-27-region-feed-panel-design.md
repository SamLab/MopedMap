# Лента постов: Ярославская область и соседи (правый верхний угол)

Дата: 2026-08-27
Статус: проект (spec)

## Цель

Добавить в генерируемый HTML-файл карты небольшое окно в правом верхнем углу —
ленту постов с радаров, касающихся **Ярославской области и шести соседних регионов**
(Тверская, Вологодская, Костромская, Ивановская, Владимирская, Московская).

Окно помогает быстро видеть свежие предупреждения БПЛА по интересующему региону,
не кликая по маркерам.

## Требования

1. Окно расположено в правом верхнем углу, поверх карты, небольшого размера, прокручиваемое.
2. В ленте — посты из **всех каналов**, регион которых относится к 7 регионам.
3. Регион поста определяется по `subject`-ам его итоговых маркеров.
   Один пост = одна строка ленты.
4. Лента строится из **итоговых маркеров** (`posts_data`) — тех же, что рендерятся на карте
   (уже прошли фильтры сводок/рекламы/памяток и т.п.).
5. Временное окно: **4 часа** (как данные карты). Показывать до **~20 последних строк**.
6. **Дедупликация каналов**: если один и тот же пост (похожий текст) пришёл из нескольких
   каналов — показать один раз, объединив источники (например «locatorru / radar_yar76»).
7. **Закрепление Ярославской области**: посты, чей регион — Ярославская область,
   всегда идут первыми (pinned-группа); посты соседних регионов — ниже.
   Внутри каждой группы сортировка по времени (новые сверху).
8. Отрисовка — CSS-панель + лёгкий JS. Сборка данных — на стороне Python в `generate_html`.

## Архитектура

### Python: `build_region_feed(posts_data, max_items=20)`

Новая функция в `mopedmap.py` (рядом с `generate_html`).

Модульная константа:

```python
TRACKED_REGIONS = frozenset({
    "ярославская область", "тверская область", "вологодская область",
    "костромская область", "ивановская область",
    "владимирская область", "московская область",
})
```

Логика:

1. **Отбор маркеров**: маркер попадает в кандидаты, если его регион ∈ `TRACKED_REGIONS`.
   - Регион маркера = `subject` (lower). Если `subject` пуст — взять
     `CITY_DB[name_lower].subject` (как в `generate_html`).
2. **Формирование постов**:
   - Ключ поста — нормализованный текст: `sanitize_popup_text(text)` → strip → collapse whitespace
     (заголовок/канал/метаданные уже убирает `sanitize_popup_text`).
   - Один пост = один ключ. Для каждого:
     - `time` — максимальный (самый свежий) среди маркеров поста.
     - `sources` — упорядоченные уникальные источники, объединённые через `, `.
     - `regions` — упорядоченные уникальные регионы маркеров поста.
     - `text` — первая строка текста (выдержка), через существующую чистку.
     - `pinned` — `True`, если «ярославская область» ∈ `regions`.
3. **Сортировка**: `pinned` (по убыванию: True сверху), затем `time` (по убыванию).
4. **Лимит**: обрезать до `max_items`.
5. **Возврат**: список `dict`, сериализуемый в JSON:
   `{time, sources, regions, text, pinned}`.

Время хранить в готовом для отображения виде `ЧЧ:ММ МСК` (или `ДД.ММ ЧЧ:ММ` если старше текущего дня),
плюс исходную строку `time` для сортировки.

### HTML/JS: рендеринг

В `generate_html`:

- `feed_json = json.dumps(build_region_feed(posts_data), ensure_ascii=False)`.
- CSS: абсолютная панель поверх карты:
  - `position:absolute; top:56px; right:12px; z-index:1000; width:320px; max-height:42vh;`
    (ниже шапки карты, чтобы не перекрывать header).
  - Белый фон `rgba(255,255,255,0.97)`, радиус, тень, `display:flex; flex-direction:column`.
  - Заголовок панели + кнопка сворачивания (▾/▸).
  - Список строк `overflow-y:auto`.
- Строка поста:
  - Верхняя строка: время + источник (бейдж), регион(ы) — мелким текстом.
  - Ярославские посты — выделенным стилем (яркая рамка/фон) + метка «Яр».
  - Выдержка текста — 2–3 строки, `-webkit-line-clamp`.
- JS: из `feed_json` отрисовать строки; кнопка сворачивает/разворачивает панель.
  Если лента пуста — скрыть панель.

### Взаимодействие с существующим кодом

- `generate_html` вызывается один раз и получает `posts_data` (уже дедуплицированные
  маркеры). Функция `build_region_feed` вызывается внутри `generate_html` перед
  сборкой HTML-строки.
- Вёрстка карты (`#map`, header, footer) не меняется — панель добавляется как
  отдельный абсолютно позиционированный элемент.

## Тестирование

- **Unit-тест `build_region_feed`**:
  - регион ∈ 7 → пост попадает; регион вне → нет.
  - маркер без subject → подставляется `CITY_DB[name].subject`.
  - два маркера с одинаковым текстом (разные каналы) → один пост, источники объединены.
  - pinned: Ярославский пост выше не-ярославского при одинаковом времени.
  - сортировка по времени внутри группы.
  - лимит `max_items`.
- **Регрессия**: существующие 24+ документированных кейсов — генерация HTML не ломается
  (панель не влияет на маркеры/заливку). Прогон `process_posts` + `generate_html`.

## Решения

- **Не использовать live-обновление на JS**: страница и так перегенерируется каждые 5 мин,
  лента согласована с картой на момент генерации.
- **Не разделять на отдельный endpoint**: всё в одном статичном HTML-файле.
- **Дедуп по нормализованному тексту**, а не по `(source, time)` — устойчиво к
  разному времени постинга копий из разных каналов.
